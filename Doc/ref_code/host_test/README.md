# 离线验证（宿主机，无硬件）

`../reference_src/Foc/` 是纯数学层（只依赖 `<math.h>`/`<stdint.h>`/`config.h`），因此可以在宿主机上
零成本回归。本目录就是这么一套回归：**不需要 ARM 工具链、不需要开发板、不需要电机**。

## 用法

```powershell
cd Doc\ref_code\host_test
.\build_and_run.ps1              # 编译 + 运行，退出码 0 = 全部通过
.\build_and_run.ps1 -Keep        # 保留生成的 exe
.\build_and_run.ps1 -Gcc C:\path\to\gcc.exe
```

只依赖宿主机 gcc（MinGW-w64）。脚本会自动在 PATH 与几个常见 MinGW 安装位置里找 gcc。

## 为什么这套验证值得保留

上游 spec §11 把"纯数学层 + 单元级自测"列为 P1a 的第一件事，本工程也已有"主机自测 252 用例"。
这份脚本是同一思路的一个具体范例，尤其是 **第 5、6 两组的写法**值得借鉴：

- **第 5 组**：不去测"占空比在 [0,1] 内"（钳位会让边界值恰好等于 1.0，判不出来），
  而是测**线性度**——`span == √3·A` 在限内成立、越限后被压缩。这样线性区上限是被"证明"出来的，
  而不是靠试几个点。
- **第 6 组**：除了验证"正常情况正确"，还专门验证**"配置错误能不能被发现"**。结论是
  残差门限对系统性配置错误只有 29.9% 的检出率——这比"通过"更有价值，直接指向了必须补的
  方向自检（见 `../README.md` 第 6 节陷阱 4）。

## 文件说明

| 文件 | 说明 |
| :--- | :--- |
| `test_foc_algorithm.c` | 全部检查项 |
| `stubs/encoder.h` | 桩：替代上游 `Hw/encoder.h`（只需 `ENCODER_CPR`），让 `foc_vernier.c` 脱离硬件编译。`stubs/` 必须排在 include 路径最前 |
| `build_and_run.ps1` | 一键编译 + 运行。**刻意保持纯 ASCII**：Windows PowerShell 对无 BOM 的 `.ps1` 按 ANSI 代码页解析，中文串会导致解析失败；脚本内已把控制台切到 UTF-8，因此 C 源文件里的中文输出正常显示 |
