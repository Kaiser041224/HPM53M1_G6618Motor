# Gui 视觉设计系统

- 版本：v2.0（2026-09-30）
- 风格定位：**TNO 硅晶之梦 · 复古未来主义（Retro-futurism）· 合成器浪潮（Synthwave）**
- 适用对象：`Gui/app`（Flutter 上位机）；同时作为固件 USB Terminal 的配色基准
- 配套：`tokens.css`（可直接引用）· `fonts/`（OFL 字体）· `../templates/gui-main.html`（规范模板）· `../previews/gui-main.png`

> **本目录所有色值均由脚本从参考图逐像素量取，非目测。**
> 复现：`powershell -NoProfile -File ../tools/measure-colors.ps1`

---

## 1. 风格一句话

**深墨底 + 霓虹青主调 + 多重发丝线 + 直角 + CRT 辉光。**

不是温润的档案纸，也不是冷灰的现代扁平 —— 是**上世纪的机器面板被做成了发光屏幕**。

## 2. 色板

### 2.1 基底 —— 极暗蓝黑 → 青绿

实测基底前两位揭示**双段偏色**，不是单一色调：

| Token | 色值 | 实测占比 | 偏色 |
| :--- | :--- | ---: | :--- |
| `--bg-void` | `#04080C` | — | 蓝黑（实测下延） |
| `--bg-base` | `#081018` | **55.2%** | **蓝黑**（R8 G16 **B24**） |
| `--bg-panel` | `#0A161A` | — | 青绿（向次位收敛） |
| `--bg-raise` | `#102024` | 3.4% | 青绿 |
| `--bg-hover` | `#162C30` | 3.7% | 青绿 |
| `--bg-active` | `#1C383C` | 4.2% | 青绿 |

> 实测次位 `#081010`（16.9%，R8 G16 **B16**，青绿）。
> **深处偏蓝黑，面板层偏青绿**，梯度由蓝黑向青绿展开。
> **背景不是中性灰** —— 换 `#121212` 一类会立刻失去合成器浪潮的味道。

### 2.2 强调色 —— 按色相家族实测峰值

| 家族 | **峰值色** | 像素数 | 定位 |
| :--- | :--- | ---: | :--- |
| **青 Cyan** | **`#58C8C0`** | **14,604** | **主强调** |
| **黄 Yellow** | **`#C8C000`** | 4,084 | **次强调** |
| 绿 Green | `#40B040` | 2,813 | 状态 · 正常 |
| 红 Red | `#F88070` | 1,365 | 状态 · 故障 |
| 蓝 Blue | `#085890` | 685 | 深底色块 |
| 品红 Magenta | `#A02048` | **396** | **几乎不存在（1.5%）** |

> ### ⚠ 实测推翻的常见印象
> 合成器浪潮通常被理解为**青 + 热粉 `#FF00FF`**。
> 但实测品红**仅占 1.5%**，真实次强调是**黄 `#C8C000`**。
> 这是更偏 **CRT 终端（青 + 琥珀）** 的配色，不是迈阿密风云式粉青。**以实测为准。**

### 2.3 文字 —— 半透明是刻意的

全部使用 **rgba 而非实色**。实色文字会"贴"在背景上，半透明才像悬浮在 CRT 光晕里。

| Token | 值 | 用途 |
| :--- | :--- | :--- |
| `--fg` | `rgba(184,212,210, 0.76)` | 主文字 |
| `--fg-strong` | `rgba(127,227,219, 0.94)` | 数值（最亮，视觉焦点） |
| `--fg-dim` | `rgba(110,143,142, 0.66)` | 次级文字 |
| `--fg-mute` | `rgba(74,102,104, 0.78)` | 标签 / 单位 |

### 2.4 轮廓辉光 —— 四层叠加

单层 `text-shadow` 只会糊。拆四层才有"灯管"的层次：

```css
--glow-1: 0 0 1px  rgba(127,227,219,.85)   /* 紧贴字形的芯 */
--glow-2: 0 0 6px  rgba(88,200,192,.48)    /* 内晕 */
--glow-3: 0 0 18px rgba(88,200,192,.24)    /* 外晕 */
--glow-4: 0 0 34px rgba(88,200,192,.11)    /* 远晕 */
--stroke: 0.4px rgba(127,227,219,.46)      /* 轮廓描边 */
```

**轮廓描边不可省** —— 没有它，多层辉光会让字形边缘糊掉、笔画黏连。

#### 分层给光，不是整屏发光

整屏都发光等于都不发光。按重要性分三级：

| 层级 | 元素 | 强度 |
| :--- | :--- | :--- |
| **强**（四层 + 描边） | 大数值、设备艺术字、标题 | 最亮 |
| **弱**（内晕 + 外晕） | 参数值、条形数值、图例 | 中等 |
| **极弱**（仅 4px 内晕 .15） | 标签、单位、表头 | 几乎不发光，退到后面 |

**层级由辉光强度承担，不只是字号。**

#### 状态色辉光绝不串色

`--glow-yellow / --glow-green / --glow-red / --glow-pink / --glow-violet` 各自独立。
黄色告警发黄光，红色故障发红光。用统一青色辉光去套会让红色数字泛青边，**状态语义即被污染**。

### 2.5 数据系列色（示波器 / 多通道）

前两色取自 UI 实测色板以保证同源，后续引入固件 Terminal 的蒸汽波光谱：

| 系列 | 色值 | 来源 |
| :--- | :--- | :--- |
| S1 | `#58C8C0` | 实测青（与 UI 主调一致） |
| S2 | `#C8C000` | 实测黄 |
| S3 | `#FF87D7` | 蒸汽波 212 粉 |
| S4 | `#AF87FF` | 蒸汽波 141 紫 |
| S5 | `#87FFAF` | 蒸汽波 121 薄荷 |
| S6 | `#F88070` | 实测红 |

> 两端由此共享视觉血统；UI chrome 严格用实测色板，蒸汽波光谱只进图表。

## 3. 结构母题（全部实测）

### 3.1 直角，不是切角

**实测结论：面板角为 90° 直角。** 像素位图显示竖线直接接入横线，无对角线过渡。
> 曾有视觉描述称"切角（chamfered）"—— **测量推翻了它**。

### 3.2 多重发丝线框

边框**不是单线**。实测一个表头下沿：

```
y = 203   ████████████  亮线 1px   #58C8C0
y = 204   （空）
y = 205   ────────────  暗线 1px   #14393C
y = 210   ────────────  暗线 1px   #14393C
```

**「一亮两暗」三线叠加**，线宽**恒为 1px**。厚重感靠叠线，不靠加粗 —— 单线框会立刻显得单薄。

### 3.3 分割线：全页只用少量

板块之间**不用边框**，靠三样连接：

1. **无边框** —— 板块本身无外框；数据网格只保留内部 1px 细线（那是数据分隔，不是面板框）
2. **一亮两暗分割线** —— 上条母题用作板块间主分割
3. **板块标题下沿** —— 同一母题收窄版

> 规范模板全页仅 **3 条**醒目分割线。**分割线是稀缺资源**，多了就不显眼。

### 3.4 分段条（LED 语汇）

实测数据区使用水平分段条：**9px 高实心段 + 2px 间隙**。
是 LED／示波器刻度语汇，**不是平滑进度条**。

### 3.5 图表：实心填充 + 双向网格

实测经济界面图表构造：

| 元素 | 构造 |
| :--- | :--- |
| **饼图** | **实心楔形** —— 无描边、无分隔缝、无阴影 |
| **面积图** | **实心填充**（`fill-opacity` 半透明），不是描边细线 |
| **网格** | **双向细线**（横竖都有），暗青 1px |

实现：饼图用 CSS `conic-gradient`（天生实心无缝），面积图用 SVG `polygon`。

### 3.6 其他母题

CRT 辉光 · 网格/点阵底纹 · 刻度线 · 十字准星。

## 4. 布局规则

### 4.1 单页平铺

**参数与状态监视同屏**，不用导航栏切换。自上而下：状态监视 → 曲线 → 参数。

### 4.2 连接选项卡固定在左上角

连接控件是面板**左上角第一个元素**，点击展开详细设置（链路选择 / 地址 / 握手能力 / 链路质量）。

展开面板**相对整个顶栏定位**（`position:absolute; top:100%`），落在顶栏下方 ——
不可用 `position:absolute` 相对选项卡自身，那会**遮挡右侧的设备标识**。

### 4.3 设备型号不做常驻标题

**产品名（Gui）不常驻面板**。设备型号是**从设备读来的**，不是面板上写死的：

- **未连接**：占位框 `DEVICE ID PENDING`，不预先假定在跟什么设备说话
- **已连接**：型号出现在**连接选项卡右侧**，由 `PROTO_INFO` 握手取得

### 4.4 设备 ASCII 标识

字形与色序**必须与固件 USB 终端完全一致**，否则同一设备在两处长不一样。

- 字形：**38 列 × 5 行**，UTF-8 块字符
- 色序：终端 256 色 **45 → 51 → 141 → 207 → 213**

| 行 | 256 色 | RGB |
| :--- | ---: | :--- |
| 1 | 45 | `#00D7FF` |
| 2 | 51 | `#00FFFF` |
| 3 | 141 | `#AF87FF` |
| 4 | 207 | `#FF5FFF` |
| 5 | 213 | **`#FF87FF`** |

> **色值必须用脚本提取，不可手抄。** 手抄已出过两次错：把 213 写成 `#FF87D7`（那是 212）、
> 漏掉第 1 行的前导空格（导致错位一列）。
> 复现：`powershell -NoProfile -File ../tools/extract-device-art.ps1`

## 5. 字体

| 角色 | 字体 | 授权 |
| :--- | :--- | :--- |
| **标题 / 导航 / 按钮** | **Electrolize** | **SIL OFL 1.1** |
| 备选标题 | Aldrich | SIL OFL 1.1 |
| **数值 / 参数名** | **Cascadia Mono** | **SIL OFL 1.1** |
| **中文** | **Noto Sans SC**（Light / Regular / Medium） | **SIL OFL 1.1** |
| 中文描述文字 | Noto Serif SC | SIL OFL 1.1 |

字体文件与授权原文见 `fonts/`。**授权结论详见 [`font-licensing.md`](font-licensing.md)。**

### 排版规则

- 标题：**全大写 + 字距 0.14–0.22em**（硬性要求，不用大写立刻失去气质）
- 数值：**等宽 + tabular figures + 右对齐**，刷新时宽度不得变化
- 中文：**不追求窄体**（免费字体里不存在真正的中文窄体），改用细字重 + 字距模拟技术感
- 精度由**量纲**决定：电流 3 位、母线 1 位、频率 2 位 —— 不用全局常量

## 6. 状态语义

| 状态 | 色值 | 说明 |
| :--- | :--- | :--- |
| `normal` | `#40B040` | 正常 / 链路就绪 |
| `warn` | `#C8C000` | 接近门限 |
| `fault` | `#F88070` | 已触发 |
| `latched` | `#FF9E96` | 锁存待清（故障强化版） |
| `stale` | `#4A6668` | **数据失效** |
| `pending` | `#B8B848` | 待落盘 |

### 三条不可让步的规则

1. **颜色不得单独承载语义** —— 一律「色 + 图标 + 文字」三重编码。
   需应对色觉差异、灰度截图、投影仪、被截屏转发。
2. **`0` 与 `—` 必须区分** —— 轮询失败时不得继续显示旧值冒充实时。
   每个实时值携带 `live / stale / unknown` 三态。
3. **状态色辉光不得串色**（见 §2.4）。

## 7. 与固件 Terminal 的关系

**同源，无需折中。** 硅晶之梦本身就是霓虹青 + CRT，与终端蒸汽波同一家族。

- Terminal：高饱和霓虹（欢迎界面，数秒一次性，追求记忆点）
- Gui：同一色相家族的**低明度版本**（长时间工作面，追求可读性）

差异只在**明度与使用面积**，色相一致；设备 ASCII 标识直接复用终端字形与色序。

## 8. 应用检查清单

- [ ] 背景是否带青绿/蓝黑偏色（不是中性灰）？
- [ ] 边框是否为**多重 1px 发丝线**（一亮两暗），而非单线或粗线？
- [ ] 角是否为**直角**？
- [ ] 文字是否**半透明 rgba**（不是实色）？
- [ ] 数值/标题是否有**多层轮廓辉光 + 描边**，标签是否已退到极弱？
- [ ] 状态色辉光是否与状态同色（未串色）？
- [ ] 标题是否**全大写 + 字距**？
- [ ] 数值是否**等宽 tabular + 右对齐**？
- [ ] 板块之间是否**无边框**，且分割线数量克制？
- [ ] 状态是否用了**色 + 图标 + 文字**三重编码？
- [ ] 失效数据是否降级为 `stale` 并显示 `—`？
- [ ] 色值是否全部来自 `tokens.css`，没有硬编码？
- [ ] 设备标识是否由 `extract-device-art.ps1` 提取（未手抄）？

## 附：复现工具

```powershell
# 从 screenshots/ 重量色板（基底占比 + 色相家族峰值）
powershell -NoProfile -File ../tools/measure-colors.ps1

# 从固件源码提取设备 ASCII 艺术字（字形 + 色序 + HTML 片段）
powershell -NoProfile -File ../tools/extract-device-art.ps1
```

> **两个脚本都必须保留 UTF-8 BOM。**
> Windows PowerShell 5.1 会把无 BOM 的 UTF-8 脚本按系统 ANSI 码页（本机为 GBK）解码，
> 导致中文注释与**块字符**损坏、脚本报错。用编辑器重存时请确认编码为「UTF-8 with BOM」。

### 测量口径

- **基底**：`(max+min)/2 < 46` 且 `(max-min)/max < 0.75`，量化到 8 阶后统计占比
- **强调**：`(max-min)/max >= 0.40` 且 `(max+min)/2 >= 80`，按色相家族分组
  （青 160–200° / 绿 90–160° / 黄 40–70° / 品红 280–345° / 红 345–15° / 蓝 200–250°），
  取各家族出现次数最多的量化色为峰值色
