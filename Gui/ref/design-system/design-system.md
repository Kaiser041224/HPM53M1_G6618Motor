## 1. 风格一句话

**深墨底 + 霓虹青主调 + 多重发丝线 + 直角 + CRT 辉光。**

不是温润的档案纸，也不是冷灰的现代扁平 —— 是**上世纪的机器面板被做成了发光屏幕**。

### 2.1 基底 —— 极暗蓝黑 → 青绿

实测基底前两位揭示**双段偏色**，不是单一色调：

| Token | 色值 | 实测占比 | 偏色 |
| :--- | :--- | ---: | :--- |
| `--bg-void` | `#04080C` | — | 蓝黑（实测下延） |
| `--bg-base` | `#081018` | **55.2%** | **蓝黑**（R8 G16 **B24**） |
| `--bg-panel` | `#0A161A` | — | 青绿（向次位收敛） |

| `--bg-active` | `#1C383C` | 4.2% | 青绿 |

> 合成器浪潮通常被理解为**青 + 热粉 `#FF00FF`**。

### 2.3 文字 —— 半透明是刻意的 ⚠ 被 v5 取代

> **⚠ v5 取代**：v5 文字改用**实色发光值**（主值 `#B8F4F8` / 正文 `#B2C9C2` /
> 次级 `#4E8E92`，见 §2.6.1），不再用下方半透明 rgba。以下为 v4 依据。

全部使用 **rgba 而非实色**。实色文字会"贴"在背景上，半透明才像悬浮在 CRT 光晕里。

| Token | 值 | 用途 |
| :--- | :--- | :--- |
| `--fg` | `rgba(184,212,210, 0.76)` | 主文字 |
| `--fg-strong` | `rgba(127,227,219, 0.94)` | 数值（最亮，视觉焦点） |
| `--fg-dim` | `rgba(110,143,142, 0.66)` | 次级文字 |
| `--fg-mute` | `rgba(74,102,104, 0.78)` | 标签 / 单位 |

### 2.4 轮廓辉光 —— 四层叠加 ⚠ 被 v5 取代

> **⚠ v5 取代**：v5 数值采用「发光管」单层短辉光（如
> `text-shadow: 0 0 6px rgba(<专色>,.35)`）+ 1px 暗底勾勒（`.outline`），
> 不再使用下方四层大半径叠加。以下为 v4 依据。

单层 `text-shadow` 只会糊。拆四层才有"灯管"的层次：

```css
--glow-1: 0 0 1px  rgba(127,227,219,.85)   /* 紧贴字形的芯 */
--glow-2: 0 0 6px  rgba(88,200,192,.48)    /* 内晕 */
--glow-3: 0 0 18px rgba(88,200,192,.24)    /* 外晕 */
--glow-4: 0 0 34px rgba(88,200,192,.11)    /* 远晕 */
--stroke: 0.4px rgba(127,227,219,.46)      /* 轮廓描边 */
```

**轮廓描边不可省** —— 没有它，多层辉光会让字形边缘糊掉、笔画黏连。

#### 分层给光，不是整屏发光

整屏都发光等于都不发光。按重要性分三级：

| 层级 | 元素 | 强度 |
| :--- | :--- | :--- |
| **强**（四层 + 描边） | 大数值、设备艺术字、标题 | 最亮 |
| **弱**（内晕 + 外晕） | 参数值、条形数值、图例 | 中等 |
| **极弱**（仅 4px 内晕 .15） | 标签、单位、表头 | 几乎不发光，退到后面 |

**层级由辉光强度承担，不只是字号。**

#### 状态色辉光绝不串色

`--glow-yellow / --glow-green / --glow-red / --glow-pink / --glow-violet` 各自独立。
黄色告警发黄光，红色故障发红光。用统一青色辉光去套会让红色数字泛青边，**状态语义即被污染**。

#### 2.6.5 VFD 竖排发光管条构造（v6 定稿）

| 项 | 规格 |
| :--- | :--- |
| **细管周期** | **4px**：暗缝 `.5px` / 羽化 `1px` / 亮芯 `1.5px @85%` / 羽化 `1px` |
| **未点亮管芯** | 幽灵基态 α≈`.028` |
| **spill 照亮** | 亮缘外 **30px** 内暗管渐亮（α `.05 → .12`，衰减遮罩 + 溢光） |
| **雾面三层光** | 半径 **4 / 10 / 22px**（α `.5 / .3 / .18`） |
| **封装 · 凹槽** | 上暗内影 + 槽底反光 |
| **封装 · 玻璃罩** | 顶光 `.045` / 边角 `.025` / 底暗 `.07`（高光已压制） |
| **封装 · 落座** | 底部落座阴影 |
| **门限刻度** | 50% / 85% 青刻度（α`.3`） |

## 3. 结构母题（全部实测）

### 3.1 直角，不是切角

**实测结论：面板角为 90° 直角。** 像素位图显示竖线直接接入横线，无对角线过渡。
> 曾有视觉描述称"切角（chamfered）"—— **测量推翻了它**。

### 3.2 多重发丝线框 ⚠ 被 v5 取代

> **⚠ v5 取代**：v5 面板外框改为**单一 1.5px 青色勾勒**（§2.6.2），
> 行分割、标题/组线按角色固定色（低亮青 / 低亮紫），不再用「一亮两暗」三线。
> 以下为 v4 依据。

边框**不是单线**。实测一个表头下沿：

```
y = 203   ████████████  亮线 1px   #58C8C0
y = 204   （空）
y = 205   ────────────  暗线 1px   #14393C
y = 210   ────────────  暗线 1px   #14393C
```

**「一亮两暗」三线叠加**，线宽**恒为 1px**。厚重感靠叠线，不靠加粗 —— 单线框会立刻显得单薄。

### 3.3 分割线：全页只用少量 ⚠ 被 v5 取代

> **⚠ v5 取代**：v5 数据行**逐行使用低亮青 `#173E44` 行分割**（§2.6.2），
> 分割线不再「稀缺」；「全页仅 3 条」「禁逐行」的描述作废。以下为 v4 依据。

板块之间**不用边框**，靠三样连接：

1. **无边框** —— 板块本身无外框；数据网格只保留内部 1px 细线（那是数据分隔，不是面板框）
2. **一亮两暗分割线** —— 上条母题用作板块间主分割
3. **板块标题下沿** —— 同一母题收窄版

> 规范模板全页仅 **3 条**醒目分割线。**分割线是稀缺资源**，多了就不显眼。

### 3.4 分段条（LED 语汇）⚠ 被 v5 取代

> **⚠ v5 取代**：分段条演进为 **VFD 竖排发光管条**（§2.6.5），
> 不再是「9px 实心段 + 2px 间隙」。以下为 v4 依据。

实测数据区使用水平分段条：**9px 高实心段 + 2px 间隙**。
是 LED／示波器刻度语汇，**不是平滑进度条**。

### 3.5 图表：实心填充 + 双向网格

实测经济界面图表构造：

| 元素 | 构造 |
| :--- | :--- |
| **饼图** | **实心楔形** —— 无描边、无分隔缝、无阴影 |
| **面积图** | **实心填充**（`fill-opacity` 半透明），不是描边细线 |
| **网格** | **双向细线**（横竖都有），暗青 1px |

实现：饼图用 CSS `conic-gradient`（天生实心无缝），面积图用 SVG `polygon`。

### 3.6 其他母题

CRT 辉光 · 网格/点阵底纹 · 刻度线 · 十字准星。

## 4. 布局规则

### 4.1 单页平铺

**参数与状态监视同屏**，不用导航栏切换。自上而下：状态监视 → 曲线 → 参数。

### 4.2 连接选项卡固定在左上角

连接控件是面板**左上角第一个元素**，点击展开详细设置（链路选择 / 地址 / 握手能力 / 链路质量）。

展开面板**相对整个顶栏定位**（`position:absolute; top:100%`），落在顶栏下方 ——
不可用 `position:absolute` 相对选项卡自身，那会**遮挡右侧的设备标识**。

### 4.3 设备型号不做常驻标题

**产品名（Gui）不常驻面板**。设备型号是**从设备读来的**，不是面板上写死的：

- **未连接**：占位框 `DEVICE ID PENDING`，不预先假定在跟什么设备说话
- **已连接**：型号出现在**连接选项卡右侧**，由 `PROTO_INFO` 握手取得

### 4.4 设备 ASCII 标识

字形与色序**必须与固件 USB 终端完全一致**，否则同一设备在两处长不一样。

- 字形：**38 列 × 5 行**，UTF-8 块字符

## 5. 字体 —— CRT 终端字体栈

选型来自 **TNO 硅晶之梦模组本体解包**：其 `interface/TNO_fonts.gfx` 的
首个字体即 `vt323_72_WT_outline`（DEC VT320 终端体）。故拉丁与数字一律 VT323；
VT323 **不含汉字**（U+4E00+），汉字另配同为像素位图的 Fusion Pixel。

| 角色 | 字体 | 授权 | 随包 |
| :--- | :--- | :--- | :--- |
| **拉丁 / 数字 / 单位** | **VT323** | SIL OFL 1.1 | ✓ 153 KB |
| **汉字（正文 / 标题）** | **Fusion Pixel 12**（12px 原生） | SIL OFL 1.1 | ✓ 7.05 MB |
| **汉字（标签类）** | **Fusion Pixel 10**（10px 原生） | SIL OFL 1.1 | ✓ 3.86 MB |
| **区分 / 增强** | **Silkscreen**（像素强调体） | SIL OFL 1.1 | ✓ 32 KB |
| 密集等宽（备选） | Share Tech Mono | SIL OFL 1.1 | ✓ 43 KB |

**合计 11.1 MB**，全部随 `Gui/app/assets/fonts/` 打包，注册于 `pubspec.yaml`。
授权原文同目录（`OFL-*.txt`），并在 `main.dart` 里登记进 `LicenseRegistry`。

### ★ 像素网格（最容易踩的坑）

Fusion Pixel 是**位图式**字体，只在**原生尺寸及其整数倍**上锐利。
把 12px 压到 10px 等于落在 0.833 倍网格 —— 像素边界对不齐，边缘发虚。
故**按用途分配原生档，而不是随意缩放**：

| 档位 | 用途 | 依据 |
| :--- | :--- | :--- |
| **10px** | 标签 / 单位 / 注记 | 汉字 advance 恰为字号本身，10px/字 ≈ 原先 9px Noto + 0.14em 字距的 10.26px，**不会撑破既有行宽** |
| **12px** | 正文、中文标题 | 像素网格主档 |
| **24px** | 确需放大的标题 | 2 倍，仍为整数倍故保持锐利 |

> **VT323 不含 `█`（U+2588）**，而设备 ASCII 艺术字整幅由块字符构成 ——
> 该处必须用 Fusion Pixel，否则艺术字会渲染成豆腐块。
> 已写成回归测试（`theme_test.dart`）。

### 排版规则

> **⚠ v5 取代**：字号具体档位改见 **§2.6.4**（参数名 12px / 数值 36px /
> 单位 12px / 标题 18px）。本表保留字体分工与网格约束。
> **注意**：v5 数值加大到 36px，需重新核对既有单行布局是否会溢出。

- 标题：**全大写 + 字距 0.10–0.16em**（硬性要求，不用大写立刻失去气质）
- 数值：**等宽 + tabular figures + 右对齐**，刷新时宽度不得变化
- **中文层级不靠字号拉开** —— 像素字体放大即失真。改由颜色、字距与
  下方亮线承担。这正是 CRT 终端「同字号、靠亮度分层」的做法
- 精度由**量纲**决定：电流 3 位、母线 1 位、频率 2 位 —— 不用全局常量
- **尺寸受布局约束**：改动字号前先跑测试，`label` 承载中西混排注记，
  放宽会撑破既有单行布局（曾出现 34px 溢出）

**授权结论详见 [`font-licensing.md`](font-licensing.md)。**

## 6. 状态语义

> v5 决定**状态语义统一落在六色光谱内**（§2.6.1）：翠绿=正常、橙=警告、
> 红=故障；不再单列一套状态色。v4 旧值（`#40B040` / `#C8C000` / `#F88070` …）
> 已退役。

| 状态 | 色值（v5） | 说明 |
| :--- | :--- | :--- |
| `normal` | 翠绿 `#3DDB6E` | 正常 / 链路就绪 |
| `warn` | 橙 `#F08030` | 接近门限 |
| `fault` | 红 `#FF4D4D` | 已触发 |
| `latched` | 红 `#FF4D4D` | 锁存待清（**靠图标强化**区分于 fault，不另配色） |
| `stale` | 次级 `#4E8E92` | **数据失效**（退后） |
| `pending` | 白青 `#B8F4F8` | 待落盘（中性，靠图标） |

### 三条不可让步的规则

1. **颜色不得单独承载语义** —— 一律「色 + 图标 + 文字」三重编码。
   需应对色觉差异、灰度截图、投影仪、被截屏转发。
2. **`0` 与 `—` 必须区分** —— 轮询失败时不得继续显示旧值冒充实时。
   每个实时值携带 `live / stale / unknown` 三态。
3. **专色随量纲、绝不串色**（见 §2.6.1 / §2.6.3）—— 数值专色由其量纲决定，
   不用统一青色套所有读数。

## 7. 与固件 Terminal 的关系

**同源，无需折中。** 硅晶之梦本身就是霓虹青 + CRT，与终端蒸汽波同一家族。

- Terminal：高饱和霓虹（欢迎界面，数秒一次性，追求记忆点）
- Gui：**v5 起同为发光管语汇**（六色光谱，§2.6），但**按角色分工、控制发光面积**
  —— 面板大面积仍是暗底，发光只落在框线、数值、管条与徽标上，兼顾长时间工作面可读性。

差异只在**发光面积与角色分工**，色相家族一致；设备 ASCII 标识直接复用终端字形与色序。

## 8. 应用检查清单

- [ ] 背景是否带青绿/蓝黑偏色（不是中性灰）？
- [ ] 面板外框是否为**青 1.5px 勾勒**；行分割是否**低亮青**、标题/组线是否**低亮紫**（按角色固定）？
- [ ] 角是否为**直角**？
- [ ] 参数名是否**一律青色**，数值专色是否由**量纲派生**（§2.6.3）？
- [ ] 状态色是否落在**六色光谱**内（翠绿/橙/红…），而非另起一套？
- [ ] 字阶是否为 v5 值（参数名 12px / 数值 36px / 单位 12px / 标题 18px）？
- [ ] 标题是否**全大写 + 字距**？
- [ ] 数值是否**等宽 tabular + 右对齐**？
- [ ] 门限条是否为 **VFD 竖排发光管**构造（§2.6.5），而非平滑进度条？
- [ ] 状态是否用了**色 + 图标 + 文字**三重编码？
- [ ] 失效数据是否降级为 `stale` 并显示 `—`？
- [ ] 色值是否全部来自 `tokens.css`，没有硬编码？
- [ ] 设备标识是否由 `extract-device-art.ps1` 提取（未手抄）？

> 导致中文注释与**块字符**损坏、脚本报错。用编辑器重存时请确认编码为「UTF-8 with BOM」。

### 测量口径

- **基底**：`(max+min)/2 < 46` 且 `(max-min)/max < 0.75`，量化到 8 阶后统计占比
- **强调**：`(max-min)/max >= 0.40` 且 `(max+min)/2 >= 80`，按色相家族分组
  （青 160–200° / 绿 90–160° / 黄 40–70° / 品红 280–345° / 红 345–15° / 蓝 200–250°），
  取各家族出现次数最多的量化色为峰值色
